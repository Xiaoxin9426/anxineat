# 营销活动模块（秒杀 / 口令 / 0元兑换）实现方案

> 状态：**✅ 已确认，进入编码阶段**（2026-09-03）。原需求文档将营销活动列为开放问题，§8 的 7 条决策已全部拍板，详见 §8。
>
> 本文档在现有架构（Spring Boot 3 + MyBatis-Plus + MySQL 8，金额「分」、折扣「万分比」、并发用 DB CAS + 乐观锁 `version`、优惠券四态 `UNUSED/LOCKED/USED/EXPIRED`）之上设计，复用既有 `coupon_template` / `user_coupon` / `point_record` / `product_sku` 机制，避免重复造轮子。

---

## 1. 目标与范围

| 子功能 | 一句话定义 | 复用现有能力 |
|--------|-----------|-------------|
| **秒杀 FlashSale** | 指定 SKU 在固定时段以活动价限量售卖 | 价格走下单链路重算；库存用 `version` CAS 扣减（同 `product_sku.deductStock`） |
| **口令 Command** | 用户在活动页输入口令串，命中即发奖（券/积分/免单） | 发券复用 `user_coupon` 四态 + 乐观锁；积分复用 `point_record` |
| **0元兑换 ZeroExchange** | 用积分（或 0 门槛）兑换指定商品免费券/直接免单 | 券走 `coupon_template`(`NO_THRESHOLD`,`amount=`商品价)；或建 0 元订单 |

---

## 2. 统一活动模型（生命周期 / 权限 / 发现共用）

沿用代码库已有先例：`coupon_template`（主表）+ `coupon_scope`（明细）拆分。营销活动同样采用 **「主表 `marketing_activity` + 各类型明细表」**：

- **`marketing_activity`**：管控生命周期、门店范围、上下架、排序、发现列表。三种类型共用。
- **明细表**：`flash_sale` / `command_activity` / `zero_exchange_activity`，按 `activity_id` 关联。

> 备选（更轻量）：三张完全独立的表，各自带 `status/start_time/end_time/store_id`。若产品确认三种活动差异极大、几乎不共用 UI，可降级为此方案。本方案默认采用统一主表。

### 2.1 活动状态机
```
DRAFT 草稿 ──发布──▶ PUBLISHED 已发布 ──到点──▶ ONGOING 进行中 ──到点/手动──▶ ENDED 已结束
   │                                                                          │
   └──────────────────────── 关闭 CLOSED（任意非进行态可关闭，不可逆）──────────┘
```
- 仅 `ONGOING` 对用户可见可参与；`PUBLISHED` 可在后台预告。
- 后台定时任务或请求时按 `start_time/end_time` 推进 `PUBLISHED→ONGOING→ENDED`（复用现有 `scheduling` 定时任务风格）。

## 3. 数据模型（新增 DDL，MySQL 8 / utf8mb4）

```sql
-- 营销活动主表（三种类型共用生命周期/权限/发现）
CREATE TABLE `marketing_activity` (
  `id`           BIGINT      NOT NULL AUTO_INCREMENT,
  `type`         VARCHAR(16) NOT NULL COMMENT 'FLASH_SALE / COMMAND / ZERO_EXCHANGE',
  `title`        VARCHAR(128) NOT NULL,
  `store_id`     BIGINT      NOT NULL DEFAULT -1 COMMENT '-1 表示全门店',
  `status`       VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT/PUBLISHED/ONGOING/ENDED/CLOSED',
  `start_time`   DATETIME    DEFAULT NULL,
  `end_time`     DATETIME    DEFAULT NULL,
  `banner_image` VARCHAR(255) DEFAULT NULL,
  `sort`         INT         NOT NULL DEFAULT 0,
  `created_at`   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_type_status` (`type`, `status`),
  KEY `idx_store_status` (`store_id`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='营销活动主表';

-- 秒杀明细：每个 SKU 在一个活动内一条
CREATE TABLE `flash_sale` (
  `id`             BIGINT   NOT NULL AUTO_INCREMENT,
  `activity_id`    BIGINT   NOT NULL,
  `store_id`       BIGINT   NOT NULL,
  `sku_id`         BIGINT   NOT NULL,
  `activity_price` BIGINT   NOT NULL COMMENT '活动价（分）',
  `total_stock`    INT      NOT NULL DEFAULT -1 COMMENT '秒杀总量，-1 不限',
  `sold_stock`     INT      NOT NULL DEFAULT 0,
  `per_limit`      INT      NOT NULL DEFAULT 1 COMMENT '每人限购件数，0=不限',
  `version`        INT      NOT NULL DEFAULT 0 COMMENT '乐观锁，CAS 扣减',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_activity_sku` (`activity_id`, `sku_id`),
  KEY `idx_activity` (`activity_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='秒杀明细';

-- 口令明细
CREATE TABLE `command_activity` (
  `id`               BIGINT   NOT NULL AUTO_INCREMENT,
  `activity_id`      BIGINT   NOT NULL,
  `store_id`         BIGINT   NOT NULL,
  `command_text`     VARCHAR(64) NOT NULL COMMENT '口令串，如 AXN666',
  `reward_type`      VARCHAR(16) NOT NULL COMMENT 'COUPON 发券 / POINTS 发积分 / PRODUCT_FREE 免单券',
  `coupon_template_id` BIGINT DEFAULT NULL COMMENT 'reward_type=COUPON 时必填',
  `point_amount`     BIGINT   DEFAULT NULL COMMENT 'reward_type=POINTS 时发放积分',
  `product_sku_id`   BIGINT   DEFAULT NULL COMMENT 'reward_type=PRODUCT_FREE 时免单商品',
  `total_limit`      INT      NOT NULL DEFAULT -1 COMMENT '总领取次数，-1 不限',
  `claimed_count`    INT      NOT NULL DEFAULT 0,
  `per_user_limit`   INT      NOT NULL DEFAULT 1,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_command` (`activity_id`, `command_text`),
  KEY `idx_activity` (`activity_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='口令明细';

-- 0元兑换明细
CREATE TABLE `zero_exchange_activity` (
  `id`             BIGINT   NOT NULL AUTO_INCREMENT,
  `activity_id`    BIGINT   NOT NULL,
  `store_id`       BIGINT   NOT NULL,
  `product_sku_id` BIGINT   NOT NULL,
  `point_cost`     BIGINT   NOT NULL DEFAULT 0 COMMENT '兑换所需积分，0=纯免费',
  `total_limit`    INT      NOT NULL DEFAULT -1 COMMENT '总兑换次数，-1 不限',
  `exchanged_count` INT     NOT NULL DEFAULT 0,
  `per_user_limit` INT      NOT NULL DEFAULT 1,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_activity_sku` (`activity_id`, `product_sku_id`),
  KEY `idx_activity` (`activity_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='0元兑换明细';

-- 参与记录（口令/0元兑换的每人限领 + 幂等；秒杀限购也可复用）
CREATE TABLE `activity_record` (
  `id`           BIGINT   NOT NULL AUTO_INCREMENT,
  `activity_id`  BIGINT   NOT NULL,
  `user_id`      BIGINT   NOT NULL,
  `type`         VARCHAR(16) NOT NULL,
  `reward_detail` VARCHAR(255) DEFAULT NULL COMMENT '如 coupon_id / 发放积分数 / 免单sku',
  `biz_no`       VARCHAR(64) DEFAULT NULL COMMENT '幂等号：type+activity_id+user_id',
  `created_at`   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_biz_no` (`biz_no`),
  KEY `idx_user_activity` (`user_id`, `activity_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='活动参与记录';
```

## 5. 与现有核心模块的集成点

### 5.1 秒杀 × 下单链路（关键）
在 `OrderService.preview()` / `submit()` 中识别 `activity_type=FLASH_SALE` 的条目：
1. **价格**：以 `flash_sale.activity_price` 覆盖 `unitPrice`，并参与现有折扣重算（秒杀与券互斥，见 §6）。
2. **库存扣减（CAS，复用 `product_sku` 套路）**：
   ```sql
   UPDATE flash_sale
     SET sold_stock = sold_stock + #{qty}, version = version + 1
     WHERE id = #{id} AND version = #{oldVersion}
       AND (total_stock = -1 OR sold_stock + #{qty} <= total_stock);
   ```
   影响行数=0 → 抛 `FLASH_SOLD_OUT`。
3. **限购**：`activity_record` 中同 `(activity_id,user_id)` 已购数量 + 本次 ≤ `per_limit`（0 表示不限）。
4. **释放**：订单取消 / 超时未支付时，回退 `sold_stock`（同 `restoreStock` 仅 `sold_stock>0` 才减）。
5. `order_item` 写入 `activity_id` / `activity_type` 便于对账与数据看板。

### 5.2 口令 / 0元兑换 × 发奖
- **发券**：直接复用现有「领券」逻辑（`CouponService.claim(templateId, userId)`），写入 `user_coupon`（`UNUSED`，四态 + `version` 乐观锁），`biz_no` 防重复。
- **发积分**：复用 `pointRecord` 写入（`type=EARN_*` 或新增 `EARN_ACTIVITY`），`biz_no` 幂等。
- **0元免单券**：发放一张 `coupon_template`（`type=NO_THRESHOLD`, `amount=`该 SKU 价格, `scope_type=PRODUCT`, `ref_id=skuId` 的 `coupon_scope`）；用户后续正常下单即用券抵扣到 0。
  - *备选*：直接建 `payAmount=0` 的自提订单并完成 `PAID→COMPLETED`，跳过券。方案待产品确认（见 §6）。
- **幂等与限领**：`activity_record` 以 `biz_no = type+activity_id+user_id` 唯一约束防重复领取；`claimed_count/exchanged_count` 用 CAS 自增并校 `total_limit`、`per_user_limit`。

## 6. 叠加 / 互斥规则（✅ 已确认）

现有 `coupon_template.stackable` 已定义「券 × 会员等级折扣」叠加开关；**秒杀与券/积分/会员折扣互斥**已由产品确认（§8 第 4 条）。

确定规则：
- **秒杀价不可再叠加**会员等级折扣、优惠券、积分抵现——秒杀即最低价。下单重算时，命中 `FLASH_SALE` 的 item 直接跳过 `levelDiscountAmount` / `couponAmount` / `pointAmount`。
- 口令 / 0元兑换**发放的券**，按普通券规则走，遵循其自身 `stackable` 开关。
- 多个活动同店并存时，一个订单的单个 item 仅能归属一个活动（以 `order_item.activity_id` 标记唯一来源）。
- ⚠️ 实现提示：互斥判定要在 `OrderService.preview()` 与 `submit()` **两处都做**——preview 决定前端展示，submit 才是服务端重算的权威入口，只改一处会出现「显示有优惠、下单被拒」的不一致。

## 8. ✅ 产品决策（已确认，2026-09-03）

原 §8 的 7 条开放问题已全部拍板。以下为**权威结论**，编码严格照此执行：

| # | 议题 | 决策 | 落地影响 |
|---|------|------|---------|
| 1 | **秒杀库存** | **独立库存池** | 秒杀用 `flash_sale.sold_stock`/`total_stock` 独立扣减（CAS + `version`），**不触碰 `product_sku.stock`**。秒杀售罄不影响正价销售，正价库存也不被秒杀吃掉。取消/超时回退 `sold_stock`。超卖由 CAS 条件 `total_stock=-1 OR sold_stock+qty<=total_stock` 拦截，影响行数=0 抛 `FLASH_SOLD_OUT`。 |
| 2 | **秒杀限购** | `per_limit` **默认 1**（可配置，0=不限） | 下单时校验 `activity_record` 中同 `(activity_id,user_id,type=FLASH_SALE)` 累计数量 + 本次 ≤ `per_limit`，超出抛 `FLASH_PER_LIMIT`。 |
| 3 | **口令** | **每人限领 1 次 + 可分享 + 大小写不敏感 + 去除首尾空格** | 口令本身公开可分享（不限总人数，除非配 `total_limit`）；`per_user_limit=1`，靠 `activity_record.uk_biz_no` 幂等。匹配前对输入 `trim()` 并统一转大写，与 `command_text`（存大写）比对。 |
| 4 | **0元兑换门槛** | **支持积分门槛**，每人限 `per_user_limit`（默认 1） | `zero_exchange_activity.point_cost`：`0` = 纯免费仅限量；`>0` = 需消耗该积分并写 `point_record`（`biz_no` 幂等）。总量 `total_limit`（-1 不限）用 CAS 自增 `exchanged_count` 校验。 |
| 5 | **免单履约形态** | **发券，用户再下单**（不建 0 元单） | 发放 `coupon_template`（`type=NO_THRESHOLD`、`amount`=商品价、`scope_type=PRODUCT` + `coupon_scope.ref_id=skuId`）。订单金额/优惠明细/对账口径与正常单完全一致，**不为 0 元单写任何特殊分支**。 |
| 6 | **权限** | **超管统一配置** | `marketing_activity.store_id` 保留但默认 `-1`（全门店）；后台活动管理挂在 `/api/admin/marketing/*`，复用超管鉴权，**不做门店数据隔离、不给店员开权限**。 |
| 7 | **审核/上下架** | **无需审核流，运营直接发布** | 状态机简化为 `DRAFT → PUBLISHED → ONGOING → ENDED / CLOSED`，运营在后台直接发布/关闭，无审核态。 |

### 8.1 决策带来的两处方案收敛
- §5.2 中「直接建 0 元订单」的**备选方案作废**，仅保留发券路径。
- §6 的叠加规则由「建议」升级为**确定规则**，见更新后的 §6。
